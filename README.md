# nrSidelink

A 3GPP **Release 16 NR sidelink (V2X, Mode 2)** protocol stack in MATLAB, written as an
executable specification: clause-cited, portable to C and HDL, and verified against the
specifications rather than against itself.

It runs end to end — a packet is generated by an application model, crosses the MAC SAP on a
logical channel, wins a resource through sensing-based Mode-2 selection, is transmitted, crosses
a channel, and is received and delivered — and it measures **latency against the packet delay
budget** and **throughput**, which is what the whole thing exists for.

Two fidelities share one stack:

| | what it is | speed |
|---|---|---|
| **SLS** (system level) | many UEs, PHY replaced by a measured BLER table | 50 UEs × 2 s ≈ 10 s |
| **LLS** (link level) | one link, real waveform through OFDM, sync, channel estimation | ~1 slot at a time |

The LLS *measured* the table the SLS reads, so they are not two models — they are one model at
two resolutions, and a test asserts they agree.

## Quick start

```matlab
cd '.../nrSidelink'
addpath(pwd)

% One system-level run: 50 UEs, 4000 slots (2 s at mu=1), seed 7
k = harness.sls.run(50, 4000, 7);
disp(k)

% Unicast instead of broadcast
k = harness.sls.run(20, 2000, 7, 'unicast');

% Everything passes?
test.runAllTests
```

`k` is the KPI struct. The fields that matter:

| field | meaning |
|---|---|
| `latencyMeanMs`, `latencyP50/P90/P99Ms` | end-to-end, measured from packet **generation** |
| `withinPdb` | fraction meeting the packet delay budget |
| `goodputKbps`, `perUeKbps` | delivered **payload** only — no headers, no padding |
| `prr` | packet-level: did *anyone* decode it. Reads ~1.0 in any dense scenario |
| `prrLink`, `prrByDistance` | **per-link** reliability — the one to quote |
| `nExpired`, `nCongestionDrop`, `nRlf` | why packets died, counted separately |
| `txPerDelivery` | transmissions spent per delivered packet |
| `cbrMean`, `nReeval`, `nPreempt` | channel busy ratio and clause 5.22.1.2a activity |

> **`prr` and `prrLink` are different numbers and both are reported.** `prr` asks "did any
> receiver decode it", which a packet needs for its latency to be defined — but in a dense
> scenario the nearest neighbour always decodes, so it reads 1.0 regardless of the channel.
> `prrLink` asks "of the receivers that could have heard it, how many did". Quote that one.

Directory structure is the protocol stack. Inside `+phy/`, the split is by **specification**,
because the five PHY specs divide the work along real functional lines.

```
+phy/

  +ts38212/    CRC, polar, LDPC, rate matching, SCI formats, TB chains     29
  +ts38213/    control procedures: sync, PSFCH resource, Mode-2 control    13
  +ts38214/    data procedures: sensing, Mode-2 selection, MCS/TBS, pool   14
  +ts38215/    measurements: SL-RSRP, SL-RSSI, CBR, CR                      6
  +chan/       PSBCH / PSCCH / PSSCH / PSFCH transmit and receive chains    8
  +rx/         non-normative receiver — OUR performance lives here
    +ce/ +eq/  channel estimation, zero-forcing equalisation                3
    +sync/     S-PSS search, S-SSS detect, CFO estimate                     3
    +det/      blind PSCCH search, PSFCH resource sweep                     2
    +policy/   the Mode-2 scheduler: T1/T2, L_subCH, S_A draw, PDB         12
  +lib/        wrapped generics: OFDM, polar, LDPC, LLR, Gold, CRC         22
+sap/          cross-layer structs: packet context, MAC SAP, PHY SAP       14
+mac/          38.321 §5.22 transmit + §5.22.2 receive + §6.1.6 mux/demux  27
+rf/           RF stage — our boundary, no 3GPP SAP exists                  2
+app/          traffic generation (periodic CAM)                            1
+harness/      +sls/ system level, +lls/ link level, channel, PHY abstraction
+test/         28 test files, four package runners
+rlc/ +pdcp/ +sdap/ +pc5s/    upper layers — NOT BUILT
Documentations/               the spec PDFs. The source of truth
nrv2x-matlab/                 earlier unverified prototype — DO NOT USE
```

### Normative vs ours
Any package named after a specification, plus `+chan/`, `+mac/`, `+cfg/` and the planned upper
layers, is **normative**: bit-exact against any other compliant implementation, subject to
`.claude/rules/normative-packages.md` (flat interfaces, no hidden state, no magic numbers,
clause-cited headers). `+phy/+rx/`, `+phy/+lib/`, `+harness/`, `+app/`, `+rf/` and any
`+policy/` are **ours** to tune and replace — toolbox calls are expected there.

## Packet flow: generation to reception

One packet, through the actual modules. The slot loop is `harness.sls.slotStep`.

```
 1. TIMING    logical <-> physical slot, via phy.ts38214.poolSlotMap
 2. APP       app.trafficPeriodic -> sap.ctxInit -> sap.lchEnqueue     <-- birth, tGenSlot set
 3. BUCKETS   mac.slLcpBucket                            (cl. 5.22.1.4.1.1)
 4. EXPIRE    sap.lchExpire                              <-- PDB death, counted as a LOSS
 5. TX        (below)
 6. CHANNEL   chanmodel.slotSinr        once per slot, so interference is a slot property
 7. RX        (below)
 8. MEASURE   phy.ts38215.cbr into a rolling RSSI window
 9. PSFCH     feedback transmitted and applied           (cl. 16.3 + 5.22.1.3.3)
10. MAC       re-evaluation, pre-emption, reselection    (cl. 5.22.1.2a, 5.22.1.2)
```

**Getting a grant** (step 10, when data is pending and the trigger fires):

```
policy.remainingPdbSlots  ->  policy.pdbLogicalSlots  ->  policy.selectionRequest
                                                                  |
                                    phy.ts38214.candidateSet  <---+     sensing -> S_A
                                                                  |
                                    policy.resourcePickChained <--+     draw from S_A
                                                                  |
                                            mac.grantSelect   <---+
```

**Transmitting** (step 5):

```
sap.lchDataAvailable -> mac.slLcp -> sap.lchDequeue -> mac.muxSlSch    (a real MAC PDU)
  -> mac.harqNewTransmission -> sap.ctxTransmitted   (tTxSlot, first attempt only)
  -> phy.ts38213.slPowerControl
  -> trivEncode / frivEncode / reservationPeriodIndex  (the SCI fields OTHER UEs sense)
  -> congestionControlCheck -> policy.congestionDrop   (cl. 8.1.6, last gate)
  -> sap.txReqValidate -> rf.toAir
```

**Receiving** (step 7) — a loop over candidate **sub-channel starts**, not over transmissions:

```
for each sub-channel start:
    PSCCH decode?  -> trivDecode/frivDecode -> sensingDbRecord   (makes sensing predictive)
        PSSCH decode?
            mac.sciInterest     (cl. 5.22.2.2.1 — is this SCI for me at all?)
            mac.harqRxAssign    (process keyed on srcId+dstId+harqId, not a number)
            mac.demuxSlSch      (parse the real PDU)
            mac.pduFilter       (join identity halves across MAC subheader and SCI)
            mac.harqRxProcess   -> deliver? -> feedback?
                                     |
                              sap.ctxFinish   <-- death or delivery, tRxSlot set
```

**Every KPI is a difference between two fields of the packet context.** Latency is
`tRxSlot - tGenSlot`; access delay is `tTxSlot - tMacSlot`. Nothing reads a timing out of a
module's internals — that is what makes the instrumentation survive a rewrite.

### Why TX runs before RX
A slot-synchronous multi-UE simulator cannot evaluate any reception until every transmission
exists. It is safe because clause 8.1.4 guarantees `T1 >= T_proc,1 > 0`: a decision taken in
slot *n* can never produce a transmission in slot *n*. Everything transmitted was decided at
least `T_proc,1` slots earlier.

## Where to modify

### Change the scenario
**`+harness/+sls/scenarioInit.m`** — one file, every scenario knob:

| what | field |
|---|---|
| numerology, pool width | `scen.mu`, `scen.numSubchannel`, `scen.subchSizeRb` |
| geometry | `scen.spacingM`, `scen.posXY` |
| channel | `scen.radio.plModel` (see below), `scen.radio.noiseFigureDb` |
| traffic | `scen.traffic.sizeBytes`, `.periodSlots`, `.pqi` |
| per-UE priority | `scen.prioByUe` — a **vector**; mixed priorities are what let pre-emption fire |
| pool thresholds | `scen.pool.*` — RSRP list, CBR levels, CR limits, `slPreemptionEnable` |
| cast type | third argument to `scenarioInit`: `'broadcast'` or `'unicast'` |

> If you change `spacingM`, **recompute `scen.policy.maxEscalations`** — it is derived from the
> closest separation, and clause 8.1.4 step 7 will exhaust its bound otherwise.

### Change the scheduler
**`+phy/+rx/+policy/`** — this is the research surface, and it is where an optimisation
algorithm goes. Nothing here is normative; every function is a UE-implementation choice the
spec leaves open.

- `selectionWindow.m` — **T1 and T2.** T2 = the remaining PDB today, which is the
  collision-optimal and latency-worst corner. With a uniform draw the mean access delay is half
  the window. **This one line dominates the latency KPI**; an adaptive T2 replaces this function
  and nothing else.
- `resourcePick.m` / `resourcePickChained.m` — which resource out of S_A.
- `subchannelsForTbs.m` — L_subCH from the TB size at the chosen MCS.
- `defaults.m` — MCS, reservation period, blind retransmission count.
- `congestionDrop.m` — what to do when the CR limit would be exceeded.

### Change the channel
**`+harness/+chanmodel/`** — two functions are the whole interface:

```matlab
model = harness.chanmodel.pathlossModel('rma', struct('fcHz',5.9e9,'losMode','los', ...));
pl    = harness.chanmodel.pathloss(model, dMetres);
```

Nothing else in the tree calls a path loss implementation. **Adding TR 37.885's V2V models is
one implementation file and one `case`** in those two functions — no caller changes.

### Add a normative module
Follow `.claude/rules/normative-packages.md`, and the session pattern in `CLAUDE.md`:
clause-sweep the range, write the interface before the body, get a **worked example from the
`independent-verifier` subagent** (which never sees the code), round-trip every inverse pair.
That verifier has caught real bugs that round-trip tests could not — see below.

## How to simulate

### System level
```matlab
k = harness.sls.run(nUe, nSlots, seed);              % broadcast
k = harness.sls.run(nUe, nSlots, seed, 'unicast');   % unicast with PSFCH feedback

% Full control: build the scenario, modify it, then run
s = harness.sls.scenarioInit(50, 7);
s.traffic.sizeBytes = 190;
s.prioByUe(1:4:end) = 1;                              % a high-priority class
k = harness.sls.runScenario(s, 4000);
```
`nSlots` is **physical slots**: at mu=1 that is 0.5 ms each, so 4000 slots = 2 s.

### Link level
```matlab
s  = harness.sls.scenarioInit(4, 1);
lc = harness.lls.linkConfig(7, 3, s);                 % MCS 7, 3 sub-channels
r  = harness.lls.linkSlot(lc, 6, RandStream('mt19937ar','Seed',1), 0, []);   % 6 dB

% Acquisition, end to end: delay, CFO, noise -> timing, identity, MIB
r = harness.lls.syncSlot(0, 137, 900, 200, 1, 1, RandStream('mt19937ar','Seed',1));
```

### Regenerate the BLER table
`+harness/+phyabs/blerTable.m` is **generated**, not hand-written — measured by the LLS over the
real transmit chains. Regenerate with `harness.lls.blerSweep` and re-emit. About 45 minutes at
the current grid. See `+harness/CLAUDE.md` for why the SNR grid is non-uniform and what two
earlier grids got wrong.

### Reproducibility
Every run is reproducible from `(nUe, nSlots, seed)` alone. All randomness comes from one seeded
`RandStream` in the scenario; the modules take their draws as **inputs** and generate none. A run
that cannot be reproduced exactly is not a result.

## Verification

```
matlab -batch "test.runAllTests"       % 28 test files, four runners, ~2 minutes
```

Four levels, per `+test/CLAUDE.md`:

1. **Round trip** — every inverse pair. Cheapest, highest yield, and it proves *self-consistency,
   never correctness*: a consistently misread encoder and its matching decoder round-trip
   perfectly.
2. **Worked examples** — computed from the spec by the `independent-verifier` subagent, which
   never sees the code. **This is the only defence against a shared misreading.**
3. **Conformance vectors** — not built.
4. **Calibration** against published curves — not built.

### Bugs level 2 caught that level 1 could not
- **`slLcp`** applied clause 5.22.1.4.1.2's `SBj > 0` condition to logical-channel selection when
  it scopes to *Destination* selection — starving a channel permanently.
- **`slBchEncode`** had its cyclic-prefix mapping inverted (normal → 1386 instead of 1782). Its
  own unit test asserted the same inversion, so code and test agreed with each other. It only
  surfaced when a codeword had to *fit a resource allocation*.
- **`tbsDetermine`** dropped a `-2` term; **`cresel`** nearly lost its ×10 multiplier.

### Traps worth knowing before you touch anything
- **`sl-Priority` is inverted**: 1 is the *highest*. "Decreasing priority order" means ascending
  numeric order.
- **`C_resel` is ten times the counter**, and the counter decrements **once per reserved
  occasion**, not per transmission.
- **The keep branch re-draws the counter.** Skipping it makes a kept grant immortal.
- **Physical vs logical slots.** A delay budget is wall-clock; clause 8.1.4's windows are
  pool-slot counts. They coincide only when the pool holds every slot — which the baseline does,
  so the confusion is invisible there.
- **The MAC subheader and the SCI carry complementary halves of each identity.** Neither layer
  alone addresses a peer.
- **Pre-emption's priority comparison is strict.** `<=` gives two same-priority UEs a livelock.
- **An undetected PSFCH is a DTX, not a NACK.** DTX drives radio link failure; NACK drives
  retransmission.

## What is not built

**Upper layers.** `+rlc/`, `+pdcp/`, `+sdap/`, `+pc5s/` are empty. The largest consequence is
**no RLC segmentation**: `sap.lchDequeue` serves whole SDUs, so throughput is *under*-reported
whenever an allocation ends with partial room.

**Fading.** `+chanmodel/` is path-loss only, so the BLER table is **AWGN-only** and B5's TDL gate
is unmet. `blerLookup` *errors* rather than substituting if asked off-key.

**Mobility.** Every UE is stationary — no Doppler, no topology change.

**Mode 1.** gNB-scheduled operation (DCI 3_0, configured grants) is not modelled; this is a
Mode-2 simulator.

**Sync in the SLS.** `+sync/` runs in the LLS only; the system level assumes ideal
synchronisation, per `BUILD.md`'s explicit deferral.

**Smaller gaps:** SL-BSR / SR / CSI reporting *triggers* (cl. 5.22.1.5–.7), SL-BCH data transfer
(cl. 5.23 — the PSBCH waveform exists, the MAC wrapper does not), conformance vectors, `+vec/`.

### The honest limits on results
- **RMa is a *cellular* model on a V2V geometry.** TR 38.901's Rural Macro describes a base
  station (10–150 m) to a UE; a V2V link is two vehicles at ~1.5 m. LOS tolerates it; **NLOS does
  not** — measured, it gives no communication past 50 m. **TR 37.885's V2V Urban and Highway are
  the models a sidelink study should use**, and neither a local PDF nor a toolbox implementation
  exists for them.
- **`psfchDetect` is still a placeholder curve**, and it does not model false alarm or ACK/NACK
  confusion.
- Link-level BLER is **measured**; the map from geometry to SINR is a standards model used
  slightly out of geometry; fading is absent. **Policy-versus-policy comparisons on the same
  channel are the soundest comparison this tree supports.**

## Specifications

The PDFs in `Documentations/` are the source of truth: TS 38.211, 38.212, 38.213, 38.214,
38.215, 38.321, 38.323, 38.331. Versions are pinned in `+cfg/specVersions.json`.

**Read the PDF for anything mathematical.** `Documentations/Notes/*.md` are reformatted notes and
have twice been caught dropping mathematics the PDFs carry correctly — a lost division bar in the
`+mac/` counter-draw range, a dropped exponent in `+phy/+ts38214/`.

TR 38.901, TR 37.885 and TS 23.287 have **no local PDF**. Anything derived from them is either
taken from a toolbox implementation (RMa) or flagged as recalled rather than extracted
(`+cfg/pqiTable.m`).
